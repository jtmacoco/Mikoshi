## Problem

You have intercepted a secret message encoded as a string of numbers. The message is **decoded** via the following mapping:

`"1" -> 'A'   "2" -> 'B'   ...   "25" -> 'Y'   "26" -> 'Z'`

However, while decoding the message, you realize that there are many different ways you can decode the message because some codes are contained in other codes (`"2"` and `"5"` vs `"25"`).

For example, `"11106"` can be decoded into:

- `"AAJF"` with the grouping `(1, 1, 10, 6)`
- `"KJF"` with the grouping `(11, 10, 6)`
- The grouping `(1, 11, 06)` is invalid because `"06"` is not a valid code (only `"6"` is valid).

Note: there may be strings that are impossible to decode.  
  
Given a string s containing only digits, return the **number of ways** to **decode** it. If the entire string cannot be decoded in any valid way, return `0`.

The test cases are generated so that the answer fits in a **32-bit** integer

---
# Example 1

**Input:** `s = "12"`

**Output:** `2`

**Explanation:** `"12" could be decoded as "AB" (1 2) or "L" (12).`

## Brute Force

```python title=brute-force
class Solution:
    def numDecodings(self, s: str) -> int:
        res = [0]
        def dfs(i,cur):
            if cur and int(cur) > 26:
                return
            if i < len(s) and s[i] == '0':
                return
            if i == len(s): 
                res[0]+=1
                return
            cur=s[i]
            dfs(i+1,cur)
            if i < len(s)-1:
                cur += s[i+1]
                dfs(i+2,cur)
            else:
                return
        dfs(0,"")
        return res[0]
```

## Memoization/Top-Down

```python title=memoization
class Solution:
    def numDecodings(self, s: str) -> int:
        memo  = {}
        def dfs(i):
            if i == len(s):
                return 1
            if i in memo:
                return memo[i]
            single_digit_contribution = dfs(i+1) if s[i]!='0' else 0
            two_digit = int(s[i:i+2])
            two_digit_contribution = dfs(i+2) if 0 < two_digit <= 26 and i+1 < len(s) and s[i]!='0' else 0
                
            memo[i] = single_digit_contribution + two_digit_contribution
            return memo[i]
        return dfs(0)
```
### Decode Ways — how we got from brute force to top-down memo

#### The big idea (never changed)

At every index `i`, you have up to 2 choices:

- take **1** digit (`s[i]`) if it's not `'0'`
- take **2** digits (`s[i:i+2]`) if that forms a number from **10–26**

Count how many full paths make it to the end of the string.

#### Step 1 — Brute force (side-effect counting)

Used a shared list `res = [0]`, incremented it whenever a path reached the end. Bugs we hunted down one by one:

- Wrong index jump for the 2-digit branch (must skip 2, not 1)
- Comparing a string char to an int (`s[i] != 0` is always True — meant `'0'`)
- Off-by-one on the valid range: letters are 1–26, not 0–25
- Leading zeros: `"06"` looks fine as a number (`int("06")==6`) but isn't a valid pair — needed a check on the **string**, not just the int value
- Validity checks running on the wrong call / wrong order, letting invalid pairs like `"27"` slip through right at the base case

#### Step 2 — Reframe: make `dfs` _return_ a count

Instead of mutating a shared `res[0]`, we changed the meaning of the function to:

> `dfs(i)` = "the number of valid ways to decode `s[i:]`"

This is the key mental shift. Once `dfs` returns a number:

- **Base case:** `dfs(len(s)) = 1` — reaching the end = one complete valid decoding
- **Recursive case:** `dfs(i)` = (ways from taking 1 digit) + (ways from taking 2 digits)
- We no longer need to pass `cur` around — the validity of a group only depends on `s[i]` (and `s[i+1]`), which you can look up directly from `i`

##### Step 3 — Each branch contributes independently

Early bug: using `return 0` to bail out killed the _whole function_, even when the other branch was still valid (e.g. `"35"` — the pair is invalid, but `3` then `5` alone is fine).

Fix: compute each branch as its own value using a conditional expression, then **add them**:

```python
single_digit_contribution = dfs(i+1) if s[i] != '0' else 0
two_digit_contribution = dfs(i+2) if (0 < two_digit <= 26 and i+1 < len(s) and s[i] != '0') else 0
return single_digit_contribution + two_digit_contribution
```

Guard conditions, and why each exists:

| Check             | Why                                                             |
| ----------------- | --------------------------------------------------------------- |
| `s[i] != '0'`     | a lone `'0'` never maps to a letter                             |
| `i+1 < len(s)`    | need to confirm `s[i+1]` actually exists before slicing/pairing |
| `0 < two_digit`   | rejects `"00"`, `"0X"` style leading-zero pairs                 |
| `two_digit <= 26` | letters only go up to Z=26                                      |

#### Step 4 — Notice the repeated work

Drawing the recursion tree for `"226"` showed the same sub-problem (`i=2`, i.e. "decode the rest starting at index 2") getting computed from _two different paths_ (`2→2` and `22`). Same input `i`, same answer, computed twice — classic sign memoization helps.

#### Step 5 — Add memoization

Since `dfs(i)`'s answer depends **only on `i`** (not on any accumulated string), `i` alone is the memo key:

```python
if i in memo:
    return memo[i]
...
memo[i] = single_digit_contribution + two_digit_contribution
return memo[i]
```

Check the memo _before_ doing any work; store the result right before returning.

#### Where to go next: bottom-up DP

Top-down memo already computes `dfs(i)` using `dfs(i+1)` and `dfs(i+2)` — notice it only ever needs the _next two_ results, never anything further ahead. Bottom-up DP flips the direction: start from the end of the string and iterate backward (or start from the beginning and iterate forward), keeping just the last two computed values instead of a full recursive call stack or dictionary. Same recurrence, no recursion.
