## Problem

There are a total of `numCourses` courses you have to take, labeled from `0` to `numCourses - 1`. You are given an array `prerequisites` where `prerequisites[i] = [ai, bi]` indicates that you **must** take course `bi` first if you want to take course `ai`.

- For example, the pair `[0, 1]`, indicates that to take course `0` you have to first take course `1`.

Return _the ordering of courses you should take to finish all courses_. If there are many valid answers, return **any** of them. If it is impossible to finish all courses, return **an empty array**.

---
# Example 1

**Input:** `numCourses = 2, prerequisites = [[1,0]]`

**Output:** `[0,1]`

**Explanation:** There are a total of 2 courses to take. To take course 1 you should have finished course 0. So the correct course order is [0,1].

# Solution

>[!important] Intuition
> Use a visited global set to keep track of previous nodes we've already visited
> Use a hash set to keep track of the nodes in the current DFS call stack

```python
class Solution:
    def findOrder(self, numCourses: int, prerequisites: List[List[int]]) -> List[int]:
        adj = defaultdict(list)
        res = []
        visited = set()
        for c, p in prerequisites:
            adj[c].append(p)
        def dfs(c, hashed):
            visited.add(c)
            hashed.add(c)
            for n in adj[c]:
                if n in hashed:
                    return False
                if n not in visited:
                    if not dfs(n,hashed):
                        return False
            hashed.remove(c)
            res.append(c)
            return True

        for c in range(numCourses):
            hashed = set()
            if c not in visited:
                if not dfs(c,hashed):
                    return []
        return res
```

This is like from CS-211/311: "white/gray/black" DFS cycle detection pattern (notes in green notebook)

- **`visited`**  the global "black" set: nodes whose entire subtree has already been fully explored and found to be safe (no cycle). It persists across all the calls in the outer `for c in range(numCourses)` loop. Its job is pure efficiency: once a node's dependencies are confirmed acyclic, you never need to re-explore it from a different starting point.
- **`hashed`**  the "gray" set: nodes that are on the _current_ DFS call stack, i.e. currently being explored. A node is added to `hashed` when `dfs` is called on it, and removed right before returning `True` (the backtracking step). So at any moment, `hashed` represents the path from the current root down to wherever the recursion currently is.

The cycle check `if n in hashed: return False` is really asking "does this neighbor lead back to an ancestor of mine in the current path?
