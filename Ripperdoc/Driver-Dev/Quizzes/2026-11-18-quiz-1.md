## Questions
### Q1: Spot the bug, Error unwinding with goto
`kled_init` sets up region → kzalloc → cdev_add → class_create → device_create, with labels `err_class`, `err_cdev`, `err_buf` and `err_region` in reverse order. The bugs: `kzalloc` failure does `goto err_region` without setting `ret`, and `device_create` failure does `goto err_cdev` (skipping `class_destroy`).

**My answer:** err_class is never used; the device_create check should `goto err_class`, otherwise the class is never destroyed and memory leaks. `!kled_buf` never sets ret; it should be -ENOMEM, otherwise init returns 0 as if it succeeded.

**Grade:** correct. Both bugs found with the right fixes. The effects are worse than a leak:
- **Leaked class:** the "kled" class stays registered, so the next `class_create()` fails with `-EEXIST` and you can't reload until reboot.
- **`ret == 0`:** the module stays loaded half-built, and `rmmod` then tears down things that never existed (possible oops).

### Q2: Predict the result, File position `loff_t *ppos`
`kled_read` clamps with `*off` correctly but ends with `off += n;`. `data_len = 10`, `cat /dev/kled`. What prints? What does `off` point to, and who owns it? Give the fix.

**My answer:** cat runs forever, always starting at the beginning, because we need the global `*off`, not the local `off`. Prints 0..count bytes. `off` points to the current position, `f_pos`. One per open.

**Grade:** partial.
- **Right:** it loops forever, `off` points to `f_pos`, and there's one per open (one per `struct file`).
- **Wrong:** called `*off` "global" again. It's pointer vs pointee, not local vs global.
- **Wrong:** it prints `min(count, data_len - *off)` = 10 bytes (`0123456789`) repeatedly, not `count` bytes.
- **Missing:** didn't write the fix, `*off += n;`.

**Follow-up:** without "local"/"global", what does `off += n` change?
**My answer:** moves the pointer address; f_pos stays unchanged. **Correct.**

### Q3: What happens if…, Read/write bounds clamping
`KLED_SIZE 64`, `*off == 60`, `write(fd, buf, 10)`. Code: `if (KLED_SIZE - *off - count < 0) n = KLED_SIZE - *off;`, then copy `n`.

**My answer:** always false because `count` is size_t and can't go below 0. It writes 10 bytes where only 4 fit, so it overflows, and it returns count. Fix: `if (*off >= size) return -ENOSPC;` then `if (count > KLED_SIZE - *off) n = KLED_SIZE - *off`.

**Grade:** correct. The overflow happens on this call (6 bytes past the end), not "eventually". Nits: `size` → `KLED_SIZE`; `{return -ENOSPC;}` on one line breaks style. Alternative clamp: `n = min_t(size_t, count, KLED_SIZE - *off);`.

### Q4: Predict the result, open() flags
`if (filp->f_flags & (O_WRONLY | O_TRUNC)) data_len = 0;`. Spec: clear only if opened for writing with O_TRUNC. Cases: a) `O_WRONLY|O_CREAT|O_APPEND`, b) `O_RDONLY`, c) `O_RDWR|O_TRUNC`, d) `O_RDONLY|O_TRUNC`.

**My answer:** a) cleared, b) not cleared, c) cleared, d) cleared. Not what the spec wants. Fix: `access_mode = f_flags & O_ACCMODE; if ((access_mode == O_WRONLY || access_mode == O_RDWR) && (f_flags & O_TRUNC))`.

**Grade:** correct. All predictions and the fix are right. I added the per-case verdicts: a is wrong (append), c is right only by accident (matched via O_TRUNC), d is wrong. Nits: `flip` → `filp`; no space after `(`. Alternative: `(filp->f_mode & FMODE_WRITE) && (filp->f_flags & O_TRUNC)`.

### Q5: Predict the result, printk format specifiers / pr_fmt / sysfs param perms
`pr_fmt` = `KBUILD_MODNAME ": " fmt`, `module_param(size, int, 0444)`, `pr_info("size=%u\n", size)`, `insmod kled.ko size=-1`. Exact dmesg line? Can root write `/sys/module/kled/parameters/size`?

**My answer:** 1) `kled: size=-1`. 2) No, the permission bits are all read-only (0444).

**Grade:** partial.
- **(1) wrong:** the prefix is right, but `%u` reinterprets -1 as unsigned, so the line is `kled: size=4294967295`. Use `%d` for `int`.
- **(2) correct:** and there's a detail behind it. Root normally ignores permission bits, but a 0444 param has no write path in sysfs at all, so even root gets "Permission denied".
