## Questions
### Q1: Spot the bug, file position
```c
static ssize_t kbuf_read(struct file *filp, char __user *ubuf,
			 size_t count, loff_t *off)
{
	size_t n;

	if (*off >= data_len)
		return 0;

	n = min_t(size_t, count, data_len - *off);

	if (copy_to_user(ubuf, buffer + off, n))
		return -EFAULT;

	off += n;
	return n;
}
```

**My answer:** `buffer + off` should be `buffer + *off`, and `off += n` should be `*off += n`; "the difference is between local off and global off."

**Grade:** partial. Both fixes are right, but the model is pointer vs pointee, not local vs global. `off` is a local copy of an address; `*off` is the `f_pos` of this open file (one per `struct file`). `buffer + off` adds two pointers, so it doesn't compile (the question wrongly said it builds). `off += n` compiles and leaves the real position unchanged.

**Follow-up:** with only `off += n` left, what does `cat /dev/kbuf` do?
**My answer:** it starts from the beginning each time.
**Grade:** that's the right cause. The symptom: `cat` loops forever, because `read` never returns 0 (EOF).

### Q2: Predict the result, write bounds
`size = 16`, `*off == 10`, then `write(fd, buf, 20)`:
```c
	size_t room = size - *off;

	if (room - count < 0)
		return -ENOSPC;

	if (copy_from_user(buffer + *off, ubuf, count))
		return -EFAULT;

	*off += count;
	return count;
```

**My answer:** `size_t` can't go negative; the check should be `if (off >= room)`; the write returns garbage or a huge number because it keeps writing, so it overflows.

**Grade:** partial. The unsigned insight is right: the check is always false. But the prediction is wrong: it copies exactly 20 bytes, so 14 bytes past the allocation (heap overflow), and **returns 20** as if it succeeded. The fix is wrong too: it uses a bare `off` and compares position with room. Correct:
```c
	if (*off >= size)
		return -ENOSPC;
	count = min_t(size_t, count, size - *off);
```

### Q3: Spot the bug, init unwind (3 bugs)
```c
	ret = alloc_chrdev_region(&devt, 0, 1, "kbuf");
	if (ret)
		goto err_region;		/* bug 1 */

	buffer = kzalloc(size, GFP_KERNEL);
	if (!buffer)
		return -ENOMEM;			/* bug 2 */

	cdev_init(&cdev, &kbuf_fops);
	ret = cdev_add(&cdev, devt, 1);
	if (ret)
		goto err_free;

	cls = class_create("kbuf");
	if (IS_ERR(cls))
		goto err_cdev;			/* bug 3: ret still 0 */
	...
err_class: class_destroy / err_cdev: cdev_del / err_free: kfree / err_region: unregister_chrdev_region
```

**My answer:** `!buffer` should `goto err_region` because the region is registered; `size` isn't initialized or checked, so return -EINVAL.

**Grade:** partial (1 of 3). The kzalloc fix is right, but it also needs `ret = -ENOMEM;` before the goto. `size` validation is fair but wasn't one of the bugs. Missed:
- `alloc_chrdev_region()` failure jumps to `err_region` and unregisters a region it never got. The first step should just `return ret;`.
- `class_create()` failure leaves `ret == 0`, so init unwinds and then reports success. `rmmod` then double-frees everything. Fix: `ret = PTR_ERR(cls);`.

The label order was correct.
